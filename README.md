# OrderFlow — backend_catalog

Некоммерческий учебный backend-проект для изучения Python и разработки системы оформления заказов с нуля.

Сейчас реализован первый компонент — HTTP-каталог товаров на FastAPI с хранением в памяти. Можно создать товар, получить список товаров и найти товар по ID. PostgreSQL, сервис заказов, RabbitMQ и Telegram-уведомления относятся к следующим этапам и пока не реализованы.

## Текущий стек

- Python — локально используется версия 3.14.7.
- FastAPI — HTTP API.
- Pydantic — проверка входных данных и сериализация ответа.
- Decimal — представление цены внутри Python без использования float.
- Uvicorn — сервер приложения.
- pytest и TestClient — автоматические проверки API внутри тестового процесса.

Версии зависимостей зафиксированы в `requirements.txt` через `pip freeze`. Файл включает прямые и транзитивные зависимости текущего окружения; это не полноценный lock-файл. Установка в чистое окружение пока не проверена. Совместимость с другими версиями Python не подтверждена.

- `services/main.py` — объект FastAPI, HTTP-маршруты и преобразование отсутствующего товара в HTTP-ошибку 404.

- `services/storage.py` — список товаров в памяти, создание товара с серверным ID и поиск по ID.
- `tests/test_catalog.py` — проверки HTTP API и фикстура очистки хранилища до и после каждого теста.
- `PROGRESS.md` — файл для согласованного плана и статуса этапов; пока не заполнен.

## Подготовка окружения

Все команды ниже выполняются из корня репозитория `backend_catalog`. Инструкция рассчитана на macOS/Linux.

Для новой копии проекта с установленным Python 3.14:

```bash
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Если `.venv` уже существует и зависимости установлены, повторно создавать окружение не нужно:

```bash
source .venv/bin/activate
```

Создание окружения и установка выше — инструкция, а не отчёт об успешно выполненной чистой установке.

## Запуск каталога

Из корня репозитория, с активированным окружением:

```bash
python -m uvicorn services.main:app --host 127.0.0.1 --port 8000
```

Без активации окружения можно использовать его интерпретатор напрямую:

```bash
./.venv/bin/python -m uvicorn services.main:app --host 127.0.0.1 --port 8000
```

`services.main:app` означает: импортировать модуль `services/main.py` и запустить объявленный в нём объект `app`.

Локальный адрес API: `http://127.0.0.1:8000`. Остановка сервера — `Ctrl+C`. Команда рассчитана на локальную разработку, не на публичное production-развёртывание.

## Маршруты

| Метод | Путь | Результат |
|---|---|---|
| GET | `/health` | `200`, состояние сервиса |
| POST | `/products` | `201`, созданный товар с серверным ID |
| GET | `/products` | `200`, массив товаров; при пустом каталоге `[]` |
| GET | `/products/{product_id}` | `200`, найденный товар |

Ответ `GET /health`:

```json
{"status": "ok", "service": "catalog"}
```

### Данные товара

Входные обязательные поля: `name`, `price`, `stock`. Поле `id` назначает сервер. Любые дополнительные входные поля запрещены.

| Поле | Правило |
|---|---|
| `name` | Строка длиной 1–100 символов после удаления пробельных символов по краям; внутренние пробелы сохраняются |
| `price` | Строка с положительной ценой до `99999999.99` включительно; не более двух знаков после точки |
| `stock` | Целое число от нуля; строки, дроби и логические значения запрещены |
| `id` | Положительное целое число в ответе, назначенное сервером |

Валюта проекта — RUB; отдельного поля валюты нет. В Python цена хранится как `Decimal`, в JSON-ответе — как строка с ровно двумя знаками после точки. Например, вход `"150"` даёт ответ `"150.00"`. Неподходящая точность не округляется: `"12.340"` отклоняется, несмотря на завершающий ноль. Числовое JSON-значение `150` вместо строки тоже отклоняется.

### Ошибки

- `422` — некорректные или отсутствующие входные поля, лишние поля либо некорректный ID в пути, например `0`, `-1`, `abc`.
- `404` — товар с корректным положительным ID не найден:

```json
{"detail": "Товар не найден"}
```

## Пример ручной проверки

Сначала запусти сервер по инструкции выше. В другом терминале выполни команды ниже. Это предлагаемый сценарий, его успешное выполнение на обычном сервере пока не подтверждено.

Проверить сервис и пустой каталог:

```bash
curl -i http://127.0.0.1:8000/health
curl -i http://127.0.0.1:8000/products
```

Создать товар:

```bash
curl -i -X POST http://127.0.0.1:8000/products \
  -H 'Content-Type: application/json' \
  -d '{"name":"Блокнот","price":"150","stock":10}'
```

Ожидаемый статус — `201`. При первом создании в пустом процессе ожидается тело:

```json
{"id": 1, "name": "Блокнот", "price": "150.00", "stock": 10}
```

Получить товар и список (если в ответе другой ID, используй его):

```bash
curl -i http://127.0.0.1:8000/products/1
curl -i http://127.0.0.1:8000/products
```

Проверить отклонение числовой цены — ожидается `422` без добавления товара:

```bash
curl -i -X POST http://127.0.0.1:8000/products \
  -H 'Content-Type: application/json' \
  -d '{"name":"Ручка","price":150,"stock":10}'
curl -i http://127.0.0.1:8000/products
```

Проверить некорректный ID — ожидается `422`:

```bash
curl -i http://127.0.0.1:8000/products/0
```

После остановки сервера через `Ctrl+C` и повторного запуска `GET /products` должен вернуть пустой массив. Это ожидаемое ограничение текущего хранения в памяти.

## Автоматические тесты

Из корня репозитория:

```bash
./.venv/bin/python -B -m pytest tests/test_catalog.py -q -p no:cacheprovider --tb=short
```

`-B` отключает запись `.pyc`, а `-p no:cacheprovider` — кеш pytest.

Покрыты health, пустой каталог, создание и чтение товара, неизвестный и некорректный ID, ошибочные и отсутствующие поля, отсутствие записи после отклонённого запроса, несколько товаров и допустимые границы данных. Хранилище очищается до и после каждого теста.

Последний выполненный при подготовке README запуск:

```text
28 passed in 0.31s
```

Это проверки через TestClient внутри тестового процесса, а не запуск отдельного HTTP-сервера и не доказательство чистой установки.

## Ограничения текущей версии

- Товары находятся только в памяти процесса; после перезапуска данные теряются.
- Используется один процесс. Несколько worker-процессов не будут иметь общего списка товаров.
- ID назначается через `len(products) + 1`. Это учебное упрощение для последовательного добавления без удаления, а не конкурентно-безопасный генератор идентификаторов.
- Полноценная защита конкурентных операций не реализована.
- Изменение цены, удаление и пополнение остатков не входят в текущий API.
- БД, миграции, заказы, брокер событий, Telegram, Compose и серверное развёртывание пока отсутствуют.
- API предназначен для локальной учебной работы; публичное развёртывание требует отдельного этапа настройки и ограничения доступа.

## Цель

Конечная цель — три бизнес-сервиса отдельными процессами: каталог, заказы и уведомления. Это план, не описание уже реализованной архитектуры.
