## Точная точка остановки

**Подключение PostgreSQL к API и изолированные тесты завершены в описанных выше границах. Следующий блок — атомарное списание остатков из согласованного этапа 2.**

Предложена функция decrease_stock в services/repository.py: одним UPDATE выбирать товар по ID и достаточному stock, уменьшать остаток, через RETURNING определять результат. quantity должен быть строго положительным int без bool. Функция не должна подтверждать транзакцию самостоятельно: позже уменьшение и сохранение результата по order_id должны войти в одну транзакцию.

**На момент сохранения decrease_stock не написана и её тестов нет.** Обсуждение и задание не являются реализацией. Сначала атомарное уменьшение, затем идемпотентность по order_id и проверки недостатка/повтора/конфликта/конкуренции. Не публиковать промежуточную функцию как готовый API списания.

При начале тестов списания предложено выдавать db_session из фикстуры через yield db_session. Это пока только задание: текущая фикстура содержит обычный yield.

## Как продолжаем обучение

Пользователь пишет код. Наставник даёт конкретные словесные шаги: что вызвать, какие значения передать, куда сохранить результат и зачем. Связанные изменения выдаются одним блоком, а не обязательным ревью после каждой функции. При конкретном затруднении блок временно сужается. Полная реализация — только по прямой просьбе. Проверенный код и независимое понимание учитываются отдельно.
